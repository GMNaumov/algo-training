# Тестирование и отладка решений

[← К разделу](../README.md)

## Проверять нужно предположения

Тест — вход с известным ожидаемым результатом. Отладка — поиск причины расхождения между ожиданием и фактическими шагами. На текущем этапе выполняйте алгоритм вручную: это позволяет проверить идею до кода.

Хороший набор примеров покрывает разные свойства, а не только разные числа: пустой вход, один элемент, повторы, уже упорядоченные данные, обратный порядок, отсутствие ответа, несколько допустимых ответов и крайние значения. Не каждый случай разрешён условием; сначала уточните договорённости.

## Пример: удаление соседних повторов

Нужно оставить по одному экземпляру каждого значения в отсортированном списке 2, 2, 5, 5, 5, 9. Ожидаем 2, 5, 9. Записываем, какой элемент читаем и какая часть результата уже готова.

| Прочитано | Готовый результат |
|---|---|
| первый 2 | 2 |
| второй 2 | 2 |
| первый 5 | 2, 5 |
| оставшиеся 5 | 2, 5 |
| 9 | 2, 5, 9 |

Инвариант — утверждение, верное на каждом шаге: готовая часть содержит ровно уникальные значения прочитанного префикса в исходном порядке. Если утверждение ломается, ищите первую строку, где это произошло, а не только неверный финальный ответ.

## Приёмы проверки

**Минимальный контрпример.** Если решение неверно на длинном списке, удаляйте лишние элементы, сохраняя ошибку. Для пропуска последнего элемента достаточно списка из одного значения.

**Сравнение с перебором.** Для маленьких входов очевидное медленное решение служит эталоном. Например, быстрый поиск пары сравнивается с перечислением всех пар.

**Проверка свойств.** После сортировки элементы не убывают и их количество с частотами сохранено. Для маршрута каждая соседняя пара городов должна быть соединена дорогой. Свойства обнаруживают ошибки, даже когда точный ответ не единственный.

## Ошибки и практика

Не выводите ожидаемый ответ тем же рассуждением, которое проверяете: независимый ручной подсчёт полезнее. Один успешный пример не является доказательством. Отдельно оценивайте корректность и сложность: правильное медленное решение может не уложиться в ограничения.

**Практика.** Проверьте удаление повторов на пустом списке, одном числе, трёх одинаковых и трёх различных. Ответы: пусто, одно число, одно число, исходная тройка. Затем объясните, почему для неотсортированного списка тот же подход не удаляет все повторы.
