# Анализ сложности и Big O

[← К разделу](../README.md)

## Что измеряем

Сложность описывает, как растут затраты при увеличении входа. Обычно n — число элементов: товаров, символов или вершин. Временная сложность считает характерные операции, пространственная — объём памяти. В курсе дополнительная память не включает исходный вход; память для ответа и рекурсивного стека оговаривается отдельно.

O(f(n)) — асимптотическая верхняя граница роста: постоянные множители и небольшие добавки скрываются. Θ(f(n)) означает точный порядок роста с обеих сторон. В разговоре «алгоритм O(n)» обычно означает полезную линейную оценку, хотя формально линейная функция также ограничена сверху квадратичной.

## Пример: обработка чеков

Чтобы найти максимальный чек среди n чеков, просмотрите каждый один раз, сохраняя текущий максимум. Для 4 чеков нужно 3 сравнения, для 8 — 7. Время Θ(n), дополнительная память O(1): количество сохранённых значений не растёт вместе с входом.

Чтобы проверить все пары чеков, потребуется n(n − 1)/2 сравнений. Для 4 это 6, для 8 — 28; рост квадратичный, Θ(n²). Если же каждый шаг исключает половину отсортированного списка, шагов O(log n): среди 1024 элементов достаточно около десяти делений пополам.

| Оценка | Интуиция | Типичный пример |
|---|---|---|
| O(1) | фиксированное число действий | доступ к элементу массива по индексу |
| O(log n) | последовательное уменьшение в разы | бинарный поиск |
| O(n) | один или несколько полных проходов | поиск максимума |
| O(n log n) | логарифмическое число линейных уровней | сортировка слиянием |
| O(n²) | сравнение пар | простой поиск повторов |
| O(2ⁿ) | все подмножества | перебор наборов покупок |

## Случаи и ошибки

Линейный поиск может найти товар сразу: лучший случай O(1), худший O(n). Средний случай требует предположений о данных. Ожидаемая оценка рандомизированного алгоритма усредняет его случайные решения. Это разные основания для оценки.

Последовательные проходы складываются: n + n даёт O(n). Вложенные циклы не всегда дают n²: важно, сколько шагов реально выполняется. Для двух независимых списков размеров n и m используйте O(n + m) или O(nm), не подменяйте обе величины одной.

**Практика.** Оцените просмотр 20 чеков, затем просмотр 30 заказов: O(n + m). Оцените сравнение каждого чека с каждым заказом: O(nm). Назовите дополнительную память, если сохраняется только счётчик: O(1).
