## Как описать работу через меньшую задачу

Рекуррентное соотношение связывает величину для большого входа с той же величиной для меньшего. T(n) обозначает время обработки n элементов. Это математическое описание затрат; само по себе оно не требует реализации с рекурсией.

Например, T(n) = T(n − 1) + O(1) означает: обработать на один элемент меньше и выполнить постоянную дополнительную работу. При T(1) = O(1) получится O(n). Базовый случай необходим: без него цепочка уменьшений не имеет точки завершения.

## Пример: разделение пачки документов

Пачку из восьми документов делят пополам, независимо сортируют половины, затем сливают их за линейное время. Для степеней двойки затраты описывает T(n) = 2T(n/2) + O(n).

На верхнем уровне обрабатывается 8 документов. На следующем — две группы по 4, суммарно снова 8. Затем четыре группы по 2, опять 8. Уровней деления log₂ n, поэтому время O(n log n). Для произвольного n половины могут отличаться на один элемент, но порядок оценки сохраняется.

Сравните с поиском в одной половине: T(n) = T(n/2) + O(1) даёт O(log n). Если деление пополам сопровождается полным просмотром текущего куска, сумма n + n/2 + n/4 + … даёт O(n).

## Дерево вызовов и память

Рисуйте каждый вызов узлом, а его подзадачи — детьми. Посчитайте работу на уровне и число уровней. Это помогает не применять формулу механически.

Суммарное число вызовов не равно объёму одновременно занятой памяти. При последовательном обходе двух половин стек имеет глубину O(log n), хотя вызовов больше. Для сортировки слиянием дополнительно требуется O(n) буфера в стандартном варианте. Повторное вычисление двух почти одинаковых подзадач, как в наивном подсчёте чисел Фибоначчи, может давать экспоненциальное время.

## Самопроверка

**Практика.** Разверните T(n) = T(n − 1) + n для n = 4: работа 4 + 3 + 2 + 1, порядок O(n²). Затем разверните T(n) = T(n/2) + 1 для n = 16: четыре деления до единицы, O(log n). Не переносите оценку времени на память: для первой рекурсивной схемы глубина O(n).
