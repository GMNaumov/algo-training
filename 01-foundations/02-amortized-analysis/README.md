# Амортизированный анализ

[← К разделу](../README.md)

## Дорогой шаг в дешёвой последовательности

Амортизированный анализ оценивает суммарную стоимость последовательности операций и делит её на число операций. Он не предполагает случайные данные: гарантия относится ко всей допустимой последовательности. Отдельная операция при этом может оставаться дорогой.

## Пример: расширение списка покупок

Представьте массив с запасом места. Когда он заполнен, выделяем новый вдвое большей вместимости и переносим элементы. При добавлении восьми покупок с начальной вместимостью 1 переносы происходят при размерах 1, 2 и 4. Всего перенесено 1 + 2 + 4 = 7 элементов; ещё восемь раз записана новая покупка.

Для n добавлений сумма переносов меньше 2n, поэтому суммарное время O(n), амортизированное время добавления O(1). Но конкретное расширение при текущем размере k занимает O(k). Хранимые данные и свободный резерв занимают O(n) памяти; во время переноса старый и новый массивы могут существовать одновременно.

Идея «оплаты вперёд» даёт другое объяснение: дешёвое добавление мысленно откладывает несколько условных единиц работы на будущий перенос. Запаса достаточно, потому что расширения становятся всё реже относительно числа добавленных элементов.

## Где ещё применяется

В монотонном стеке элемент может удаляться внутри вложенного цикла. Однако каждый элемент добавляется один раз и удаляется не более одного раза: на весь вход O(n) действий. Аналогично очередь из двух стеков иногда переносит много элементов, но каждый элемент проходит перенос лишь однажды.

## Ограничения и ошибки

Рост вместимости на одну ячейку вызывает переносы 1 + 2 + … + (n − 1), то есть O(n²) суммарно. При уменьшении массива нельзя постоянно сжимать его сразу после малейшего освобождения: чередование добавлений и удалений может вызывать лишние переносы. Нужен запас между порогами расширения и сжатия.

Амортизированное O(1) не означает низкую задержку каждого запроса. Если важна максимальная пауза конкретной операции, отдельно оценивают худший случай.

**Практика.** При вместимостях 1, 2, 4, 8, 16 добавьте девятый элемент. Последнее добавление переносит 8 элементов, а за все девять добавлений переносов 15. Объясните, почему это согласуется с линейной суммой, и сравните с увеличением вместимости на одну ячейку.
