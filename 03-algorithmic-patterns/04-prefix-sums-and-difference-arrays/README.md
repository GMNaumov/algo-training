# Префиксные суммы и разностные массивы

[← К разделу](../README.md)

## Суммы до границы

Префиксная сумма P[i] — сумма первых i элементов; P[0] = 0. Удобно описывать фрагмент полуинтервалом [l, r): индекс l включён, r исключён. Его длина r − l, а сумма P[r] − P[l]. Всё до l вычитается из суммы всего до r.

## Пример: отчёты о продажах

Продажи 3, 5, 2, 6 дают префиксы 0, 3, 8, 10, 16. Продажи второго и третьего дней занимают [1, 3), сумма 10 − 3 = 7. Вместо нового обхода дней каждый отчёт использует два значения.

Подготовка занимает O(n) времени и O(n) дополнительной памяти; каждый из q запросов — O(1), всего O(n + q). После изменения исходных продаж старые префиксы перестают быть верными. Для частых изменений нужны другие структуры, например [дерево Фенвика](../../11-advanced-topics/01-fenwick-trees/README.md).

## Разности для массовых изменений

Разностный массив хранит изменения между соседними значениями. Чтобы прибавить x на [l, r), отмечаем +x на l и −x на r; последняя отметка отменяет действие для последующих позиций. Затем один проход накопления восстанавливает значения.

Например, четыре дня изначально имеют нулевые надбавки. Прибавим 10 второму и третьему дням: отметки 0, +10, 0, −10 и служебная конечная позиция. Накопление даёт 0, 10, 10, 0. Если прибавить ещё 5 третьему и четвёртому, итог 0, 10, 15, 5.

Для q таких изменений и одного финального восстановления время O(n + q), память O(n). Это удобно для заранее известных акций на диапазонах дат; немедленные запросы после каждого изменения требуют иной организации.

## Границы и практика

Пустой [l, l) имеет сумму 0. Для r = n нужна дополнительная ячейка разностей или отдельная проверка конечной границы. Большая сумма может переполнить тип, даже если отдельные значения малы. Для минимума формула вычитания префиксов не работает: минимум не имеет аналогичного обратного действия.

**Практика.** Постройте префиксы 4, −1, 2: 0, 4, 3, 5. Сумма [1, 3) равна 1. Затем на пяти нулях прибавьте 3 на [1, 4): получите 0, 3, 3, 3, 0.
