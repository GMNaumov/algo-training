# Интервалы

[← К разделу](../README.md)

## Начало, конец и правила пересечения

Интервал задаёт непрерывный диапазон: время встречи, номера мест или участок дороги. Перед решением определите, входят ли границы. Для расписаний удобны полуинтервалы [start, end): встреча 10:00–11:00 не конфликтует с начинающейся в 11:00. Для закрытых отрезков общая точка считается пересечением.

## Пример: объединение занятых периодов

Есть бронирования [1, 4), [6, 8), [2, 5), [9, 10). Отсортируем по началу: [1, 4), [2, 5), [6, 8), [9, 10). Текущий объединённый интервал сначала [1, 4). Второй пересекается с ним, расширяем конец до 5. Начало следующего 6 уже за текущим концом: сохраняем [1, 5) и начинаем [6, 8). Итог: [1, 5), [6, 8), [9, 10).

Корректность следует из порядка начал: если очередной интервал начинается после конца текущего, никакой последующий уже не соединит их через более раннее начало. Внутри группы пересечений сохраняем максимальный конец, иначе вложенный короткий интервал мог бы ошибочно сократить занятый период.

Сортировка занимает O(n log n), проход O(n). Результат занимает O(n); дополнительная память сверх ответа зависит от сортировки и копирования входа.

## Подсчёт одновременных событий

Для числа необходимых переговорных превратите каждую встречу в два события: начало +1 и конец −1. Отсортируйте события, накапливайте число активных встреч и запоминайте максимум. Для полуинтервалов в одно время сначала учитывают окончания, затем начала. Например, [1, 3), [2, 4), [3, 5) требуют две комнаты, не три.

Это называется сканирующей прямой: положение движется по времени, а состояние описывает всё активное в этой точке. Сложность O(n log n) по времени, O(n) по памяти для событий.

**Практика.** Объедините [1, 7), [2, 3), [6, 9): ответ [1, 9). Обсудите [1, 2) и [2, 3): они не пересекаются, но их можно объединить в [1, 3), если цель — представить объединение множества точек минимальным числом интервалов. Правило объединения касающихся границ задавайте явно.
