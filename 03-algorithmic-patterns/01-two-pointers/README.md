# Два указателя

[← К разделу](../README.md)

## Две позиции вместо всех пар

Указатель в этой теме — индекс или позиция, а не специальный механизм памяти C#. Два указателя позволяют согласованно просматривать последовательность. Они могут идти навстречу или в одном направлении. Ускорение появляется, когда после проверки можно обоснованно отбросить целую группу вариантов.

## Пример: две покупки из отсортированного каталога

Цены 10, 20, 35, 50, 70 упорядочены. Нужны два разных товара на 85. Ставим левую позицию на 10, правую — на 70.

1. 10 + 70 = 80, слишком мало. Переносим левую позицию на 20.
2. 20 + 70 = 90, слишком много. Переносим правую на 50.
3. 20 + 50 = 70, слишком мало. Переносим левую на 35.
4. 35 + 50 = 85 — пара найдена.

Почему при маленькой сумме можно исключить левую цену? Даже с наибольшим оставшимся партнёром она не достигает цели; остальные партнёры ещё меньше. При слишком большой сумме аналогично исключается правая цена. Сохраняется инвариант: любая ещё возможная пара находится между текущими границами.

Каждый шаг сдвигает одну границу, всего O(n) времени и O(1) дополнительной памяти. Если вход не отсортирован, предварительная сортировка обычно добавляет O(n log n); при необходимости вернуть исходные индексы их нужно сохранить.

## Другой вариант

Для удаления повторов из отсортированного массива один индекс читает вход, второй отмечает конец готовой уникальной части. Эти указатели идут в одном направлении. Важна не форма движения сама по себе, а смысл каждой позиции и уже обработанной области.

## Ограничения и практика

Для неотсортированного массива правило изменения суммы не работает. Для поиска двух разных элементов движение заканчивается, когда позиции встретились. Повторы допустимы, но перечисление всех уникальных пар требует дополнительных правил пропуска одинаковых значений.

**Практика.** Для 1, 3, 4, 7, 9 найдите сумму 10: возможны 1 + 9 и 3 + 7. Вручную найдите одну пару, затем объясните, что нужно изменить для получения обеих. Для цели 20 ответа нет.
