# Скользящее окно

[← К разделу](../README.md)

## Переиспользование соседних фрагментов

Скользящее окно — непрерывный фрагмент последовательности с левой и правой границами. При смещении мы обновляем сведения только об ушедших и пришедших элементах. Это избегает повторного подсчёта почти одинаковых фрагментов.

## Пример фиксированного окна

Число посетителей по дням: 2, 1, 5, 1, 3. Ищем самую посещаемую серию из трёх дней. Первое окно имеет сумму 8. Сдвигаем: вычитаем 2, прибавляем 1, сумма 7. Ещё сдвиг: вычитаем 1, прибавляем 3, сумма 9. Лучший фрагмент — 5, 1, 3.

Поддерживается точная сумма текущего окна; проверяются все допустимые начала. Поэтому максимум среди просмотренных сумм в конце является ответом. Время O(n), дополнительная память O(1) при доступном исходном массиве. Для потока может понадобиться хранить само окно: O(k), где k — его длина.

## Окно переменной длины

Допустим, длительности занятий положительны: 2, 1, 3, 2, бюджет 4. Нужно самое длинное непрерывное расписание с суммой не больше бюджета. Расширяем правую границу. Когда сумма превышает 4, удаляем элементы слева до восстановления условия. Получаются допустимые максимальные окна для каждого правого конца; наибольшая длина здесь 2.

Движение границ корректно благодаря положительности: добавление справа не уменьшает сумму, удаление слева не увеличивает. При отрицательных числах это основание исчезает. Например, окно с суммой больше бюджета может стать допустимым после добавления отрицательного числа; преждевременное удаление способно потерять ответ.

## Затраты и ошибки

Каждая граница движется только вперёд, значит суммарно O(n) сдвигов. Поддержка частот для окна без повторяющихся символов требует O(u) памяти для u разных символов. Вложенный цикл сжатия не делает алгоритм квадратичным, если левый индекс никогда не возвращается.

Проверяйте k = 1, k = n, k > n и правила для пустого окна. Не сбрасывайте сумму при каждом сдвиге — тогда исчезнет экономия.

**Практика.** Найдите максимальную сумму двух соседних дней в 4, 2, 7, 1: ответ 9. Затем объясните, почему тот же фиксированный размер работает и с отрицательными числами, хотя переменное окно по ограничению суммы требует иных условий.

## Примеры на C#

| Файл | Что изучать |
|---|---|
| [Canonical.cs](examples/Canonical.cs) | Явные шаги алгоритма или устройство структуры; условия и затраты объяснены в комментариях. |
| [Modern.cs](examples/Modern.cs) | Современная запись, библиотечная замена или другой компромисс по времени и памяти. |

Сначала получите ответ вручную, затем прочитайте каноничную версию и сравните с современной. В `Applications.Run` ожидаемый ответ указан первым аргументом проверки. Изменяйте вход и проверяйте, сохраняются ли условия применимости алгоритма.

Запуск из корня репозитория с установленным .NET 10 SDK:

```powershell
dotnet run --project examples/AlgoTraining.csproj -- 03-algorithmic-patterns/03-sliding-window
```

Устройство проекта, смысл современных конструкций и общие команды описаны в [инструкции запуска](../../examples/README.md). В методических темах код демонстрирует учебный сценарий; в алгоритмических — реализацию и её применение.
