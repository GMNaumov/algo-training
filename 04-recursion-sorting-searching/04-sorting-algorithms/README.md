# Алгоритмы сортировки

[← К разделу](../README.md)

## Для чего нужен порядок

Сортировка переставляет элементы по заданному правилу. После неё легче искать границы, находить соседние дубликаты и объединять интервалы. Цена подготовки оправданна, когда порядок сокращает последующую работу. Для одного поиска максимума сортировка избыточна.

**Стабильная** сортировка сохраняет исходный относительный порядок равных ключей. **Сортировка на месте** обычно означает малую дополнительную память, но отдельно учитывайте стек вызовов.

## Пример: сортировка вставками

Счета имеют суммы 7, 2, 5, 3. Первый элемент считаем готовой отсортированной частью. Вставляем 2 перед 7: 2, 7. Затем 5 между ними: 2, 5, 7. Затем 3 после 2: 2, 3, 5, 7. При каждом шаге готовая часть остаётся отсортированной и содержит ровно первые обработанные счета.

Если вход почти упорядочен, сдвигов мало. Если он обратный, каждый новый элемент перемещается через всю готовую часть.

## Сравнение подходов

| Алгоритм | Время | Дополнительная память | Особенность |
|---|---|---|---|
| Вставками | лучший O(n), худший O(n²) | O(1) | стабилен при корректном сравнении равных |
| Выбором минимума | O(n²) | O(1) | обычный вариант нестабилен |
| Слиянием | O(n log n) | O(n) | можно сохранить стабильность |
| Быстрая сортировка | ожидаемо O(n log n), худший O(n²) | зависит от рекурсии | обычный вариант нестабилен |
| Пирамидальная | O(n log n) | O(1) | использует кучу, обычно нестабильна |
| Подсчётом | O(n + U) | O(U) для частот | нужны целые ключи из небольшого диапазона U |

Ожидаемая оценка быстрой сортировки относится, например, к случайному выбору опорного. У простого рекурсивного варианта стек ожидаемо O(log n), в худшем O(n). Стабильный вариант сортировки подсчётом с отдельным выходом использует O(n + U) памяти.

## Ограничения и практика

Для сортировок только сравнениями общая нижняя граница худшего случая — Ω(n log n). Подсчёт её не нарушает: он использует дополнительную информацию о ключах.

Правило сравнения должно быть согласованным и транзитивным. Вычитание двух больших чисел ради сравнения может переполниться. Уточняйте, разрешено ли менять вход.

**Практика.** Отсортируйте вставками 4, 1, 3, 2. Затем отметьте записи (Анна, 5), (Борис, 3), (Вера, 5): при стабильной сортировке по числу 5 Анна остаётся перед Верой.
