# Поиск с возвратом

[← К разделу](../README.md)

## Перебрать варианты и отменить выбор

Поиск с возвратом, или backtracking, строит решение постепенно. На каждом шаге выбирает допустимое продолжение, исследует его, затем отменяет выбор и пробует следующее. Ветка прекращается, когда решение готово или уже ясно, что оно не сможет стать допустимым.

Это подходит для расписаний, комбинаций покупок и размещения объектов с ограничениями. Сначала определите состояние, доступные варианты, условие завершения и правило отмены.

## Пример: набор покупок на сумму 7

Есть три товара стоимостью 2, 4 и 5; каждый можно взять не более одного раза. Для каждого товара два выбора: взять или пропустить. Сначала берём 2, затем 4: сумма 6, добавление 5 превысит 7, поэтому эту ветку можно закончить. Возвращаемся, отменяем 4, берём 5: сумма 7, найден набор 2 и 5.

Ветка без 2 тоже должна быть проверена, если нужны все наборы. Каждое подмножество соответствует единственной последовательности решений «взять/пропустить», поэтому полный обход не пропускает варианты. Отсечение по превышению суммы верно только для неотрицательных цен: отрицательная цена могла бы вернуть сумму к цели.

## Восстановление состояния

Если выбор добавил товар в текущий набор и изменил сумму, возврат обязан убрать товар и восстановить сумму. Иначе следующая ветка получит чужие данные. Готовый ответ при сохранении обычно копируют: ссылка на изменяемый текущий набор не сохраняет его прежнее содержимое.

## Сложность и границы

Для n товаров есть 2ⁿ подмножеств. Сам обход дерева решений занимает O(2ⁿ); явное копирование каждого набора может увеличить затраты до O(n·2ⁿ). Глубина и текущий набор требуют O(n) дополнительной памяти без хранения всех ответов.

Повторы значений могут давать одинаковые по стоимости наборы: заранее решите, считаются ли товары различными. Отсечение ускоряет отдельные входы, но без дополнительного доказательства не меняет экспоненциальную худшую оценку.

**Практика.** Перечислите все подмножества цен 1, 2, 3 и найдите сумму 3. Ответы: товар 3 и пара 1 + 2. Затем добавьте требование «ровно два товара»: останется только пара. Объясните, как хранить число выбранных товаров и когда ветку можно остановить заранее.
