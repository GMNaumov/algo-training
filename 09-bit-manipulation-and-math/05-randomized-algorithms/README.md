# Рандомизированные алгоритмы

[← К разделу](../README.md)

## Случайность как часть метода

Рандомизированный алгоритм делает случайные выборы во время работы. В варианте Las Vegas ответ всегда корректен, но время зависит от случайности, как у Quickselect со случайным опорным. В варианте Monte Carlo время контролируется, но допускается вероятность ошибки, как при сравнении строк по случайному хешу без точной проверки.

Ожидаемая сложность усредняет случайные выборы алгоритма при фиксированном входе. Это не обещание одинакового времени каждого запуска и не предположение о случайном входе.

## Пример: победитель из потока

Заявки приходят по одной, их итоговое число неизвестно. Нужно выбрать одну равновероятно, храня только текущего кандидата. Первую заявку сохраняем. При поступлении i-й заменяем кандидата новой заявкой с вероятностью 1/i. Это резервуарная выборка для одного элемента.

После трёх заявок первая остаётся с вероятностью 1·(1 − 1/2)·(1 − 1/3) = 1/3. Вторая выбирается с вероятностью 1/2 и сохраняется с вероятностью 2/3, тоже итог 1/3. Третья выбирается непосредственно с вероятностью 1/3.

Общее доказательство: старый кандидат имел вероятность 1/(i − 1), после шага сохраняется с вероятностью (i − 1)/i, итог 1/i. Новая заявка имеет ту же вероятность. Следовательно после n поступлений все заявки равноправны.

Время O(n), дополнительная память O(1). Нужна возможность равномерно выбрать один из i исходов и достаточно широкий счётчик. Для пустого потока победителя нет.

## Перемешивание

Равномерное перемешивание Фишера — Йетса проходит позиции с конца: для текущей позиции выбирается равновероятная позиция от начала до текущей включительно и выполняется обмен. Все n! перестановок получают одинаковую вероятность. Время O(n), дополнительная память O(1).

Случайные перестановки через произвольное число обменов не гарантируют равномерность. Сортировка со случайным несогласованным сравнением тоже некорректна.

## Проверка и практика

Для воспроизводимой отладки сохраняют начальное состояние генератора и вход. Серия частотных экспериментов помогает найти грубое смещение, но не доказывает точную равномерность. Для защищённых розыгрышей дополнительно нужны требования к непредсказуемости; учебный генератор решает другую задачу.

**Практика.** После четырёх заявок вероятность каждой 1/4. Проверьте это для второй: 1/2·2/3·3/4 = 1/4. Для двух различных элементов равномерное перемешивание должно давать каждый из двух порядков с вероятностью 1/2.

## Примеры на C#

| Файл | Что изучать |
|---|---|
| [Canonical.cs](examples/Canonical.cs) | Явные шаги алгоритма или устройство структуры; условия и затраты объяснены в комментариях. |
| [Modern.cs](examples/Modern.cs) | Современная запись, библиотечная замена или другой компромисс по времени и памяти. |

Сначала получите ответ вручную, затем прочитайте каноничную версию и сравните с современной. В `Applications.Run` ожидаемый ответ указан первым аргументом проверки. Изменяйте вход и проверяйте, сохраняются ли условия применимости алгоритма.

Запуск из корня репозитория с установленным .NET 10 SDK:

```powershell
dotnet run --project examples/AlgoTraining.csproj -- 09-bit-manipulation-and-math/05-randomized-algorithms
```

Устройство проекта, смысл современных конструкций и общие команды описаны в [инструкции запуска](../../examples/README.md). В методических темах код демонстрирует учебный сценарий; в алгоритмических — реализацию и её применение.
