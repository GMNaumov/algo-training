# Поиск подстроки

[← К разделу](../README.md)

## Найти непрерывное совпадение

В поиске подстроки дан текст длины n и образец длины m. Нужно найти начало одного или всех непрерывных вхождений. Это отличается от поиска подпоследовательности: пропускать символы внутри совпадения нельзя.

## Пример: поиск кода в журнале

Текст «ababa», образец «aba». Простой способ пробует каждое начало от 0 до n − m и сравнивает символы слева направо. В позиции 0 совпадают все три. В позиции 1 первая буква b не подходит. В позиции 2 снова полное совпадение. Ответ: позиции 0 и 2.

Вхождения перекрываются: буква в позиции 2 участвует в обоих. Если после совпадения сразу перескочить на длину образца, второе вхождение потеряется. Такой перескок допустим только при отдельном требовании неперекрывающихся совпадений.

Корректность перебора проста: каждое возможное начало проверено, а принятие требует равенства всех m символов. Если m > n, вхождений нет. Для пустого образца соглашение задаётся отдельно: например, совпадение на каждой из n + 1 границ текста.

## Сложность и ускорения

В худшем случае на каждом старте сравниваются почти все m символов, время O(nm). Пример — длинный текст из a и образец из многих a с последней b. Дополнительная память O(1), не считая списка ответов. Создание отдельной копии каждого кандидата добавляет выделения памяти и обычно не нужно для самой проверки.

КМП использует самоповторы образца и даёт O(n + m). Z-алгоритм на объединённой строке тоже даёт линейный поиск. Полиномиальный хеш позволяет быстро отсеивать несовпадения, но одинаковые хеши требуют учёта коллизий. Суффиксные структуры полезны при множестве запросов к одному тексту.

Выбор зависит от сценария: для короткого образца и одного небольшого текста простой перебор может быть достаточно понятным и дешёвым; сложная подготовка окупается не всегда.

**Практика.** В «aaaa» образец «aa» встречается в позициях 0, 1, 2. Для «abc» и «abcd» ответ пуст. Затем найдите «ac» в «abc»: подстроки нет, хотя подпоследовательность есть. Объясните разницу.

## Примеры на C#

| Файл | Что изучать |
|---|---|
| [Canonical.cs](examples/Canonical.cs) | Явные шаги алгоритма или устройство структуры; условия и затраты объяснены в комментариях. |
| [Modern.cs](examples/Modern.cs) | Современная запись, библиотечная замена или другой компромисс по времени и памяти. |
| [Applications.cs](examples/Applications.cs) | Небольшие практические сценарии, вызовы реализаций и ожидаемые результаты для самопроверки. |

Сначала получите ответ вручную, затем прочитайте каноничную версию и сравните с современной. В `Applications.Run` ожидаемый ответ указан первым аргументом проверки. Изменяйте вход и проверяйте, сохраняются ли условия применимости алгоритма.

Запуск из корня репозитория с установленным .NET 10 SDK:

```powershell
dotnet run --project examples/AlgoTraining.csproj -- 10-string-algorithms/01-string-matching
```

Устройство проекта, смысл современных конструкций и общие команды описаны в [инструкции запуска](../../examples/README.md). В методических темах код демонстрирует учебный сценарий; в алгоритмических — реализацию и её применение.
