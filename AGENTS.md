# AGENTS.md

## Назначение проекта

`algo-training` — сборник учебных материалов по алгоритмам и структурам данных. Цель — провести учащегося с нулевого опыта решения алгоритмических задач до уровня собеседований в ведущие технологические компании.

Аудитория — начинающий разработчик, который знает основы C#, но пока не умеет решать алгоритмические задачи. Материалы и комментарии должны быть на русском языке и не предполагать предварительных знаний алгоритмов. Реализации используют C# 14 и .NET 10 LTS.

Проект выполняет роль учебного курса и справочника, а не прикладной программы.

## Текущее состояние

Репозиторий содержит 14 тематических разделов и 80 карточек тем в формате Markdown, а также 240 файлов примеров C# рядом с темами и общий консольный проект `examples/AlgoTraining.csproj`. Сторонних зависимостей нет.

Все 80 карточек наполнены объяснениями, примерами из жизни, пошаговыми разборами и упражнениями. По следующему запросу пользователя добавлены каноничные и современные реализации C#, небольшие практические сценарии и проверки. Индексы разделов объясняют порядок изучения и ожидаемый результат.

## Структура и навигация

Корневой `README.md` — точка входа и карта всех разделов. Каждый раздел имеет собственный `README.md` с упорядоченным списком тем. Каждая тема находится в отдельной пронумерованной папке, а её материал размещается во вложенном `README.md`.

```text
README.md
00-start-here/                 — методика обучения и решения задач
01-foundations/                — сложность, C#, коллекции .NET, отладка
02-linear-data-structures/     — линейные структуры данных
03-algorithmic-patterns/       — паттерны решения задач
04-recursion-sorting-searching/— рекурсия, сортировка и поиск
05-trees-and-heaps/            — деревья и кучи
06-graphs/                     — графы
07-dynamic-programming/        — динамическое программирование
08-greedy-algorithms/          — жадные алгоритмы
09-bit-manipulation-and-math/  — битовые операции и математика
10-string-algorithms/          — алгоритмы на строках
11-advanced-topics/            — продвинутые структуры и алгоритмы
12-interview-preparation/      — подготовка к собеседованиям
13-reference/                  — справочные материалы
```

Правила:

- Имена папок — на английском, в нижнем регистре, через дефис; числовой префикс задаёт порядок изучения.
- Заголовки и учебное содержимое — на русском языке.
- Крупные темы разбивать на вложенные самостоятельные темы, не создавая неуправляемо длинные страницы.
- При добавлении темы создавать для неё отдельную папку с `README.md`, добавлять ссылку в индекс раздела и обратную ссылку на этот индекс.
- При добавлении раздела обновлять корневой `README.md` и этот файл.
- Использовать относительные ссылки на конкретные `.md`-файлы. Не оставлять страницы вне навигации.
- Сохранять последовательность обучения: от базовых понятий к основным структурам и паттернам, затем к продвинутым темам и тренировке интервью.

## Требования к содержанию и примерам C#

Объяснения должны быть доступны новичку: раскрывать термины и интуицию, показывать идею на реальном сценарии и небольших конкретных данных, объяснять шаги и корректность подхода. Для алгоритмов и структур указывать временную и дополнительную пространственную сложность с определением переменных, условия применения, граничные случаи и типичные ошибки. Для методических тем давать конкретный сценарий работы и критерии самопроверки. Упражнения должны усложняться постепенно; по возможности давать ожидаемый ответ для проверки.

Пользователь разрешил и запросил исполняемые примеры. Для каждой темы сохранять три файла в папке `examples`: `Canonical.cs` с явными шагами, по возможности без синтаксического сахара; `Modern.cs` с уместными возможностями современного C#/.NET; `Applications.cs` с 1–2 небольшими сценариями применения алгоритмов и структур и ожидаемыми ответами. У тем с несколькими алгоритмами показывать каждый основной алгоритм и его применение. Для методики и справочника использовать учебные сценарии соответствующей темы.

Комментарии объясняют смысл состояния, инвариант, условия входа, сложность, граничные случаи и отличия вариантов. Не представлять LINQ или библиотечный вызов как бесплатную операцию. Современный вариант может быть библиотечной заменой или другим компромиссом: это нужно явно объяснять. Не усложнять каноничную реализацию ради краткости.

Пространства имён тем имеют вид `AlgoTraining.Topics.S02T05` (номера раздела и темы), что позволяет одинаковые имена `Canonical`, `Modern`, `Applications`. Класс `Applications` отмечен `[Lesson("путь/темы", "Заголовок")]` и содержит `public static void Run()`. Общий запускатель находит сценарии по этому атрибуту. Для проверки использовать `Check.Equal`, `Check.Sequence`, `Check.Throws`: они активны и в Release. Не добавлять отдельные точки входа в файлы темы.

Сохранять наполненные материалы, относительную навигацию и единые обозначения. Не возвращать страницы к заглушкам. Код дополняет объяснения, а не заменяет их. Из README каждой темы давать прямые относительные ссылки на файлы `.cs` и общую инструкцию `examples/README.md`. Факты о конкретных API проверять по официальной документации. Обновление платформы сверх .NET 10/C# 14 требует отдельной задачи.

Не превращать материалы в список готовых решений без объяснения подхода. Продвинутые темы не должны становиться неявным требованием для понимания базовых материалов.

## Технологии, сборка и тестирование

Используются .NET 10 LTS, C# 14, nullable reference types, implicit usings и предупреждения как ошибки. `global.json` задаёт SDK 10.0.100 с `latestFeature`, позволяя стабильные feature bands 10.0. Проект включает `../*/*/examples/*.cs`. Новые проекты, `.sln`, пакеты и тестовые фреймворки без необходимости не добавлять. `NuGet.Config` отключает внешние источники; все примеры используют стандартную библиотеку.

Команды из корня репозитория:

```powershell
dotnet restore examples/AlgoTraining.csproj --configfile NuGet.Config
dotnet build examples/AlgoTraining.csproj --no-restore -c Release
dotnet run --project examples/AlgoTraining.csproj --no-build -c Release -- --list
dotnet run --project examples/AlgoTraining.csproj --no-build -c Release -- 02-linear-data-structures/05-stacks
dotnet run --project examples/AlgoTraining.csproj --no-build -c Release -- --all
dotnet run --project examples/AlgoTraining.csproj --no-build -c Release -- --verify
dotnet format whitespace examples/AlgoTraining.csproj --no-restore --verify-no-changes
git diff --check
```

`--all` выполняет сценарии всех 80 тем; `--verify` — дополнительные проверки на малых входах с фиксированными seed и независимыми эталонами. Ошибка даёт ненулевой код процесса. После изменения C# выполнять сборку и подходящие проверки; для Markdown проверять относительные ссылки, навигацию и итоговый список файлов. Не создавать тесты, которые только повторяют реализацию.

В текущем окружении SDK 10.0.403 установлен локально в `.tools/dotnet`; это служебная папка, исключённая из Git. Для локального прогона путь `dotnet` можно заменить на `.tools/dotnet/dotnet.exe`. Из-за ограничений окружения процессу проверки могут потребоваться `DOTNET_CLI_HOME=.tools/cli` и `APPDATA=.tools/appdata`; пользовательские настройки постоянно не менять. Не коммитить SDK, генераторы, `bin`, `obj`, логи и временные файлы. При изменении структуры или команд обновлять этот файл и инструкцию запуска.
