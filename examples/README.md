# Как запускать и читать примеры на C#

[← Главная](../README.md)

Для всех 80 тем есть папка `examples` рядом с материалом. В ней три файла: каноничная версия, современная версия и практические сценарии с ожидаемыми ответами. Один общий [проект](AlgoTraining.csproj) собирает их вместе: создавать 80 проектов и устанавливать пакеты не требуется.

## Подготовка и запуск

Установите [.NET 10 SDK](https://dotnet.microsoft.com/en-us/download/dotnet/10.0), затем откройте терминал в корне репозитория. Нужен именно SDK, а не только Runtime. Проект использует `net10.0` и C# 14. [global.json](../global.json) разрешает стабильные SDK семейства 10.0 начиная с 10.0.100, выбирая доступный более новый feature band.

```powershell
dotnet restore examples/AlgoTraining.csproj --configfile NuGet.Config
dotnet build examples/AlgoTraining.csproj --no-restore -c Release
dotnet run --project examples/AlgoTraining.csproj --no-build -c Release -- --list
dotnet run --project examples/AlgoTraining.csproj --no-build -c Release -- 02-linear-data-structures/05-stacks
dotnet run --project examples/AlgoTraining.csproj --no-build -c Release -- --all
dotnet run --project examples/AlgoTraining.csproj --no-build -c Release -- --verify
```

Первый запуск восстанавливает только метаданные проекта: сторонних NuGet-зависимостей нет. [NuGet.Config](../NuGet.Config) отключает внешние источники. Все файлы примеров уже включены в общий проект. Если после изменений запускаете с `--no-build`, сначала повторите сборку, иначе будет выполнена прежняя версия.

После первоначальной подготовки для редактирования одной темы удобно разрешить автоматическую сборку:

```powershell
dotnet run --project examples/AlgoTraining.csproj -- 02-linear-data-structures/05-stacks
```

Ожидаемый итог `--all`: 80 тем и ноль ошибок. Число проверок выводится в конце; при расхождении программа возвращает ненулевой код. `--verify` запускает дополнительные воспроизводимые проверки на небольших входах. Неизвестная тема или неверные аргументы дают код 2.

## Порядок чтения

1. Прочитайте теорию и выпишите результат для маленького входа.
2. Откройте `Canonical.cs`. Здесь основные действия описаны явно, обычно циклами и обычными классами. Пространства имён и общие служебные типы нужны только для совместной сборки.
3. Откройте `Modern.cs`. Сравните алгоритм, удобство записи, выделения памяти и стоимость библиотечных операций. Современный вариант может использовать тот же алгоритм либо предоставлять библиотечную замену или другой компромисс; комментарии это поясняют.
4. Откройте `Applications.cs`. Метод `Run` создаёт конкретные данные, вызывает реализации и сверяет ответ. Подпись проверки описывает практический сценарий; ожидаемое значение стоит первым аргументом `Check.Equal` или `Check.Sequence`.
5. Запустите тему, измените данные, поставьте точку останова и проследите состояние. Затем восстановите реализацию самостоятельно.

Например, в теме стека проверяется вложенность скобок и отмена последнего изменения. Три первых строки вывода соответствуют правильному выражению, контрпримеру и истории отмены. Это небольшие демонстрации в памяти: они не отправляют реальные заказы, не меняют файлы и не обращаются к внешним сервисам.

Для методических тем код показывает учебные сценарии: план повторений, трассу рассуждения, измерение времени и разбор проверки. Для справочника — короткие упражнения на выбор подхода и терминологию. Они не заменяют практику общения и самостоятельное решение новых задач.

## Современные возможности в примерах

| Возможность | Смысл и ограничение |
|---|---|
| `var`, `new()`, выражения коллекций `[]` | вывод типов и более короткое создание; сама коллекция всё равно занимает память |
| `Span<T>`, `ReadOnlySpan<T>`, диапазоны `..` | работа с фрагментом без копии; `ToArray` и spread в новую коллекцию создают копию |
| Кортежи и деконструкция | именованные несколько результатов, согласованное обновление состояний |
| `record`, `record struct`, primary constructors | компактные модели данных; `record` не делает вложенные коллекции неизменяемыми |
| Pattern matching | явные случаи и проверка отсутствия значения |
| LINQ | декларативные преобразования; сортировка, группировка и материализация требуют времени и памяти |
| `yield return` | результаты выдаются по одному, перечисление выполняет отложенную работу |
| `PriorityQueue`, `TryPop`, `TryDequeue` | библиотечные операции с явно обработанным отсутствием элемента |
| `INumber<T>` | один числовой алгоритм для нескольких типов; арифметическая цена зависит от типа |
| `BigInteger` | целые без фиксированного диапазона; разрядность и затраты растут |
| Extension blocks C# 14 | современная запись членов расширения; пример находится в [шпаргалке](../13-reference/02-csharp-cheatsheet/README.md) |

Официальные пояснения: [C# 14](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/csharp-14), [generic math](https://learn.microsoft.com/en-us/dotnet/standard/generics/math), [Random.Shuffle](https://learn.microsoft.com/en-us/dotnet/api/system.random.shuffle). Новые возможности применены там, где помогают сравнению; читать все темы на самом новом синтаксисе сразу не требуется.

## Ограничения учебных реализаций

Условия входа и сложности указаны в комментариях. Для отсортированного массива порядок обычно является предпосылкой: повторная проверка всего входа внутри бинарного поиска уничтожила бы его логарифмическую оценку. Для деревьев и списков без циклов это свойство также предполагается, если метод не занимается специальной проверкой.

Точечные примеры не стремятся покрыть весь API промышленной коллекции. Например, собственная хеш-таблица демонстрирует вставку и поиск с коллизиями без удаления и роста; AVL — вставку и поиск; рекурсивные обходы могут исчерпать стек на глубоком входе. Стандартные коллекции в современных вариантах показывают альтернативу для прикладной работы.

Наивное сжатое суффиксное дерево служит для объяснения рёбер и поиска; его построение с копированием строк не является линейным алгоритмом Укконена. Двойной хеш не доказывает равенство, поэтому точные сценарии подтверждают совпадение символами. В геометрии используется `BigInteger`, чтобы произведения координат не переполнялись. В измерениях времени нет требований «быстрее N миллисекунд».

Общий [запускатель](Program.cs) находит классы сценариев по атрибуту `Lesson`. [Check](Support.cs) сравнивает результаты и работает также в Release. [Дополнительные проверки](Verification.cs) используют небольшие фиксированные и случайные входы с сохранёнными seed; отдельный тестовый фреймворк не нужен.
