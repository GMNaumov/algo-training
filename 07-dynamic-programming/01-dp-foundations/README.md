# Основы динамического программирования

[← К разделу](../README.md)

## Когда помогает запоминание

ДП полезно, если разные ветви решения приходят к одинаковым подзадачам, а ответ для большой задачи можно получить из меньших. Мы один раз вычисляем значение состояния и используем его повторно. Состояние должно хранить достаточно информации для будущего: две истории, сведённые к одному состоянию, должны допускать одинаковые продолжения с одинаковым смыслом результата.

Есть два способа вычисления: мемоизация запускает рекурсивный поиск и сохраняет ответы по мере необходимости; табуляция заранее выбирает порядок и заполняет таблицу снизу вверх.

## Пример: лестница

До верхней ступени можно шагать на 1 или 2 ступени. Сколько последовательностей шагов ведёт на ступень i? Обозначим ответ ways[i]. Последний шаг пришёл либо с i − 1, либо с i − 2, поэтому ways[i] = ways[i − 1] + ways[i − 2]. Эти группы не пересекаются: последний шаг у них различен.

База: ways[0] = 1 — один способ ничего не делать; ways[1] = 1. Далее получаем 2, 3, 5 для ступеней 2, 3, 4. На ступень 4 ведут пять последовательностей, включая 1+1+1+1, 2+1+1, 1+2+1, 1+1+2 и 2+2.

Наивная рекурсия многократно считает те же номера ступеней. В ДП каждое из n + 1 состояний вычисляется один раз за O(1) переходов: O(n) времени, O(n) памяти таблицы. Для одного итогового числа достаточно двух предыдущих значений, то есть O(1) дополнительной памяти. Рекурсивная мемоизация дополнительно использует стек O(n).

## Как проектировать решение

Запишите смысл каждого состояния полным предложением. Определите базу и невозможные состояния. Перечислите все варианты последнего действия и докажите, что ничего не пропущено и не посчитано дважды. Затем выберите порядок, в котором зависимости уже известны.

## Ошибки и практика

Не каждое ДП суммирует: для минимума берут лучший из вариантов, для существования — логическое «или». Нулевое значение может быть допустимым ответом, поэтому его нельзя всегда использовать как отметку «не вычислено». Число способов может быстро переполнить числовой тип.

**Практика.** Найдите ways[5]: 8. Затем разрешите шаги только 1 и 3: значения для 0…4 будут 1, 1, 1, 2, 3. Объясните, почему база для пустого пути остаётся единицей.

Сначала получите ответ вручную, затем прочитайте каноничную версию и сравните с современной. В `Applications.Run` ожидаемый ответ указан первым аргументом проверки. Изменяйте вход и проверяйте, сохраняются ли условия применимости алгоритма.

Запуск из корня репозитория с установленным .NET 10 SDK:

```powershell
dotnet run --project examples/AlgoTraining.csproj -- 07-dynamic-programming/01-dp-foundations
```

Устройство проекта, смысл современных конструкций и общие команды описаны в [инструкции запуска](../../examples/README.md). В методических темах код демонстрирует учебный сценарий; в алгоритмических — реализацию и её применение.
