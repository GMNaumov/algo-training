# Жадные стратегии

[← К разделу](../README.md)

## Выбор без возврата

Жадная стратегия берёт лучший доступный вариант по выбранному правилу: самое раннее окончание, наименьшую цену или наибольшую выгоду. Вычислительная простота не гарантирует глобальный оптимум. Сначала сформулируйте цель, затем правило, затем проверьте, можно ли его доказать.

## Пример: посетить больше встреч

Встречи занимают [1, 4), [3, 5), [4, 6), [5, 7), [6, 8). Нужно посетить максимум непересекающихся встреч. Сортируем по окончанию и каждый раз берём первую встречу, начинающуюся не раньше конца выбранной предыдущей.

Выбираем [1, 4), пропускаем [3, 5), выбираем [4, 6), пропускаем [5, 7), выбираем [6, 8). Получены три встречи.

Раннее окончание оставляет не меньше времени для остальных. В любом оптимальном расписании первую встречу можно заменить самой рано заканчивающейся: все последующие всё ещё поместятся. После замены остаётся такая же задача для хвоста времени. Подробный принцип — в [теме доказательств](../02-greedy-proofs/README.md).

Сортировка требует O(n log n), проход O(n), ответ O(n) памяти; вспомогательная память зависит от сортировки. Если вход уже отсортирован по окончаниям, достаточно линейного прохода.

## Почему похожие правила могут провалиться

Выбор самой рано начинающейся встречи может взять [0, 10) вместо трёх коротких [1, 2), [2, 3), [3, 4). Выбор самой короткой тоже требует отдельного доказательства и в общем случае неверен.

При разных оплатах встреч максимальное число уже не равно максимальному доходу. Например, одна длинная встреча с оплатой 100 лучше двух коротких по 10, если цель — доход. Для взвешенного расписания обычно нужен другой подход, например ДП.

## Практика и границы

Уточните, могут ли встречи касаться концами; здесь полуинтервалы разрешают это. Нулевую длительность и равные окончания обрабатывайте по договорённости.

**Практика.** Для монет 1, 3, 4 и суммы 6 жадный выбор даёт 4 + 1 + 1, а оптимум 3 + 3. Для встреч [1, 2), [2, 3), [1, 3) стратегия раннего окончания выбирает две. Объясните, почему успех на одном типе задач не доказывает любое правило «брать самое выгодное».
