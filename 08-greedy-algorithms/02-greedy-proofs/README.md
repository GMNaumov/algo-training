# Доказательство корректности жадных алгоритмов

[← К разделу](../README.md)

## Что нужно доказать

Жадный алгоритм отбрасывает альтернативы навсегда. Поэтому необходимо показать, что после каждого выбранного шага существует оптимальное решение, начинающееся с уже принятых шагов. Совпадение с перебором на нескольких примерах полезно для проверки, но не заменяет общее доказательство.

## Обменный аргумент на встречах

Пусть жадный выбор — встреча g с самым ранним окончанием. Возьмём произвольное оптимальное расписание; его первая встреча o заканчивается не раньше g. Заменим o на g. Все дальнейшие встречи начинаются после конца o, следовательно после конца g; конфликтов не появилось, число встреч не уменьшилось.

Теперь существует оптимальное расписание с первым жадным выбором. Остаётся задача для встреч, начинающихся после g. Применяем тот же аргумент к ней. Повторение доказывает оптимальность всего алгоритма, а не только первого шага.

В доказательстве важна именно цель «максимальное число». Если оплаты разные, замена o на g может уменьшить доход, и аргумент перестаёт работать.

## Ещё один обмен: очередь работ

Есть работы длительностей a и b, все доступны сразу, веса одинаковы. Минимизируем сумму времён завершения. Если сначала a, затем b, вклад этих двух работ относительно старта равен 2a + b. При обратном порядке — 2b + a. Если a ≤ b, первый порядок не хуже.

Значит любую соседнюю пару, где более длинная работа стоит раньше короткой, можно поменять без ухудшения. Повторяя обмены, получаем порядок по возрастанию длительностей. Работы после пары не страдают: суммарная длина пары не меняется. Для длительностей 3 и 1 суммы завершений соответственно 3 + 4 = 7 и 1 + 4 = 5.

## Другие схемы и ошибки

«Жадный не отстаёт» сравнивает каждый префикс жадного решения с префиксом любого конкурента. Свойство разреза доказывает безопасность рёбер минимального остова. Во всех схемах фиксируют, что сравнивается и почему локальный вывод переносится на остаток.

Не используйте фразу «очевидно выгоднее» вместо аргумента. Проверьте скрытые ограничения: разные сроки доступности, приоритеты или веса способны изменить оптимальный порядок.

**Практика.** Для длительностей 4, 2, 1 порядок 1, 2, 4 даёт завершения 1, 3, 7, сумму 11. Покажите обменом, почему порядок 2, 1, 4 хуже на единицу. Алгоритм сортировки занимает O(n log n), суммирование O(n), дополнительная память зависит от сортировки.

## Примеры на C#

| Файл | Что изучать |
|---|---|
| [Canonical.cs](examples/Canonical.cs) | Явные шаги алгоритма или устройство структуры; условия и затраты объяснены в комментариях. |
| [Modern.cs](examples/Modern.cs) | Современная запись, библиотечная замена или другой компромисс по времени и памяти. |
| [Applications.cs](examples/Applications.cs) | Небольшие практические сценарии, вызовы реализаций и ожидаемые результаты для самопроверки. |

Сначала получите ответ вручную, затем прочитайте каноничную версию и сравните с современной. В `Applications.Run` ожидаемый ответ указан первым аргументом проверки. Изменяйте вход и проверяйте, сохраняются ли условия применимости алгоритма.

Запуск из корня репозитория с установленным .NET 10 SDK:

```powershell
dotnet run --project examples/AlgoTraining.csproj -- 08-greedy-algorithms/02-greedy-proofs
```

Устройство проекта, смысл современных конструкций и общие команды описаны в [инструкции запуска](../../examples/README.md). В методических темах код демонстрирует учебный сценарий; в алгоритмических — реализацию и её применение.
