# Кучи и приоритетные очереди

[← К разделу](../README.md)

## Быстрый доступ к лучшему кандидату

Минимальная бинарная куча — почти полное бинарное дерево, где значение родителя не больше значений детей. Все уровни, кроме последнего, заполнены, последний заполняется слева. Минимум находится в корне. Порядок между соседними ветками не задан: куча не является деревом поиска.

Кучу удобно хранить массивом. При индексе узла i от нуля дети имеют индексы 2i + 1 и 2i + 2, если существуют. Приоритетная очередь использует эту идею для выдачи самого срочного или ближайшего события.

## Пример: ближайшие напоминания

Приоритеты по времени 2, 5, 3 образуют минимальную кучу. При добавлении события с приоритетом 1 ставим его в конец, затем меняем с родителем 5 и с корнем 2. Получается массив 1, 2, 3, 5. Новый минимум 1.

Чтобы извлечь минимум, переносим последний элемент 5 в корень и уменьшаем размер: 5, 2, 3. Меняем его с меньшим ребёнком 2: 2, 5, 3. Куча восстановлена. Вверх или вниз меняется только один путь, остальные отношения порядка остаются верными.

## Оценки

Просмотр минимума O(1), вставка и извлечение O(log n), потому что высота O(log n). Поиск произвольного значения O(n). Хранение O(n); просеивание может быть итеративным с O(1) дополнительной памятью, хотя расширение массива иногда требует переноса.

Построение кучи из готового массива снизу вверх занимает O(n), а не O(n log n): большинство узлов около листьев и просеиваются недалеко. Последовательные отдельные вставки имеют верхнюю оценку O(n log n).

## Границы и практика

У максимальной кучи сравнения обратные. Для равных приоритетов отдельно задайте вторичный критерий, если важен порядок поступления. Нельзя получать отсортированный результат простым чтением массива кучи; нужны повторные извлечения или отдельная сортировка.

**Практика.** В кучу 2, 5, 3 добавьте 4: получится 2, 4, 3, 5. Затем извлеките минимум: допустимый результат 3, 4, 5. Объясните, почему 4 в левом поддереве не обязано быть меньше 3 в правом.

Сначала получите ответ вручную, затем прочитайте каноничную версию и сравните с современной. В `Applications.Run` ожидаемый ответ указан первым аргументом проверки. Изменяйте вход и проверяйте, сохраняются ли условия применимости алгоритма.

Запуск из корня репозитория с установленным .NET 10 SDK:

```powershell
dotnet run --project examples/AlgoTraining.csproj -- 05-trees-and-heaps/04-heaps-and-priority-queues
```

Устройство проекта, смысл современных конструкций и общие команды описаны в [инструкции запуска](../../examples/README.md). В методических темах код демонстрирует учебный сценарий; в алгоритмических — реализацию и её применение.
