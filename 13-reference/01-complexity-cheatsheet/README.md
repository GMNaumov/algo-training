# Шпаргалка по сложности алгоритмов и структур данных

[← К разделу](../README.md)

## Обозначения и условия

n — число элементов, h — высота дерева, k — размер окна или выбранного набора, V и E — вершины и рёбра, W — числовая вместимость. O описывает верхний порядок роста. В таблицах память алгоритма — дополнительная к входу, если явно не сказано «хранение структуры».

Ожидаемая оценка зависит от случайности или предположений о хешировании; амортизированная — от суммарной стоимости последовательности. Ни одна не обещает такую задержку каждой отдельной операции.

## Структуры данных

| Структура | Поиск | Изменения | Хранение |
|---|---|---|---|
| Массив | по индексу O(1), по значению O(n) | замена O(1), сдвиг при вставке O(n) | O(n) |
| Динамический массив | индекс O(1) | конец амортизированно O(1), расширение O(n) | O(n) |
| Связный список | O(n) | O(1) при известных нужных узлах | O(n) |
| Хеш-таблица | ожидаемо O(1), худшее O(n) | аналогично поиску, расширение учитывается амортизированно | O(n) |
| BST | O(h) | O(h) | O(n) |
| Сбалансированное BST | O(log n) | O(log n) | O(n) |
| Бинарная куча | минимум O(1), произвольный ключ O(n) | вставка/извлечение O(log n) | O(n) |
| Фенвик | префикс O(log n) | точечное прибавление O(log n) | O(n) |
| Дерево отрезков | агрегат диапазона O(log n) | точечное O(log n) | O(n) |

Хеширование длинного ключа не обязано быть O(1). У обычного BST h может быть n. Стек и очередь при подходящей реализации имеют O(1) извлечение и амортизированное O(1) добавление с хранением O(n).

## Алгоритмы

| Метод | Время | Дополнительная память |
|---|---|---|
| Линейный просмотр | O(n) | O(1), если храним один ответ |
| Два указателя по упорядоченному массиву | O(n) | O(1) без предварительной сортировки |
| Сумма фиксированного окна | O(n) | O(1) для доступного массива |
| Префиксные суммы и q запросов | O(n + q) | O(n) |
| Бинарный поиск по массиву | O(log n) | O(1) итеративно |
| Сортировка слиянием | O(n log n) | O(n) |
| Quickselect со случайным опорным | ожидаемо O(n), худшее O(n²) | O(1) в итеративном варианте на месте |
| Top k минимальной кучей | O(n log(k + 1)) | O(k) |
| DFS/BFS на списках смежности | O(V + E) | O(V) без самого графа |
| Рюкзак 0/1 | O(nW) | O(W) для одного значения |
| ДП на сетке R × C | O(RC) | O(C) для одного значения |
| Перебор подмножеств | O(2ⁿ), с копированием наборов O(n·2ⁿ) | O(n) без всех ответов |
| КМП | O(n + m) | O(m), где m — длина образца |

## Пример: быстрая оценка масштаба

Для n = 100 000 полный перебор неупорядоченных пар — около пяти миллиардов проверок, линейный проход — сто тысяч шагов, n log₂ n — около 1,7 миллиона условных единиц работы. Это сравнение порядка, а не прогноз секунд: реальное время зависит от операций, среды и данных.

**Практика.** Для n объектов и m запросов линейный поиск на каждый запрос даёт O(nm). Подготовка подходящего словаря и запросы — ожидаемо O(n + m), память O(n). Объясните, при каких условиях дополнительная память оправданна, а когда одного прохода достаточно.

Подробности: [анализ сложности](../../01-foundations/01-complexity-analysis/README.md), [амортизация](../../01-foundations/02-amortized-analysis/README.md), [кратчайшие пути](../../06-graphs/06-shortest-paths/README.md).

## Примеры на C#

| Файл | Что изучать |

Сначала получите ответ вручную, затем прочитайте каноничную версию и сравните с современной. В `Applications.Run` ожидаемый ответ указан первым аргументом проверки. Изменяйте вход и проверяйте, сохраняются ли условия применимости алгоритма.

Запуск из корня репозитория с установленным .NET 10 SDK:

```powershell
dotnet run --project examples/AlgoTraining.csproj -- 13-reference/01-complexity-cheatsheet
```

Устройство проекта, смысл современных конструкций и общие команды описаны в [инструкции запуска](../../examples/README.md). В методических темах код демонстрирует учебный сценарий; в алгоритмических — реализацию и её применение.
