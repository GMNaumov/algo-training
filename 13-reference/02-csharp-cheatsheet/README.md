## Свойства, которые стоит проверить до реализации

Это памятка без программного кода. Версия C#/.NET в проекте ещё не выбрана; доступность конкретных API проверяется при будущем добавлении реализаций.

| Вопрос | Что учитывать |
|---|---|
| Помещается ли ответ? | int — 32-разрядный знаковый тип, long — 64-разрядный; суммы и произведения проверяются отдельно от входа |
| Где граница массива? | для n элементов допустимы индексы 0…n − 1; позиция n может обозначать конец диапазона, но не элемент |
| Как делятся целые? | результат округляется к нулю; остаток может быть отрицательным |
| Можно ли менять вход? | несколько ссылок могут указывать на один массив; копия стоит O(n) |
| Что считает длина строки? | единицы UTF-16, не обязательно видимые символы |
| Дёшево ли собирать строку? | строка неизменяема; повторное создание длинных промежуточных строк увеличивает копирование |
| Безопасна ли рекурсия? | глубина вызовов ограничена стеком; длинная цепочка требует внимания |
| Бесплатна ли библиотечная операция? | копирование, поиск, сортировка и материализация последовательности имеют время и память |

## Выбор коллекции по задаче

| Нужно | Подходящий кандидат | Почему |
|---|---|---|
| Хранить значения по позициям | массив или `List<T>` | прямой индекс |
| Найти заказ по номеру | `Dictionary<TKey,TValue>` | связь ключа со значением |
| Проверить уникальность | `HashSet<T>` | достаточно наличия |
| Отменить последнее действие | `Stack<T>` | LIFO |
| Обработать заявки по поступлению | `Queue<T>` | FIFO |
| Перемещать известный узел | `LinkedList<T>` | изменение соседних связей |
| Поддерживать упорядоченные ключи | `SortedSet<T>` или `SortedDictionary<TKey,TValue>` | порядок с логарифмическими изменениями |
| Извлекать минимальный приоритет | `PriorityQueue<TElement,TPriority>` | минимум без полной сортировки |

Ожидаемое O(1) словаря предполагает подходящие хеши и недорогие ключи. Поиск значения в `List<T>` остаётся O(n). Приоритетная очередь .NET извлекает меньший приоритет раньше, но для одинаковых приоритетов не обещает порядок поступления. Если он нужен, добавьте явный вторичный критерий.

## Пример проверки решения

Нужно суммировать 100 000 чеков до 100 000 каждый. Максимальная сумма 10¹⁰ не помещается в int, поэтому широкий аккумулятор требуется ещё до реализации. Если затем надо сохранить исходный порядок перед сортировкой, нужна копия с O(n) памятью. Эти решения не меняют математическую идею, но определяют корректность и фактические затраты.

**Практика.** Для отрицательного остатка −1 по модулю 5 нужен нормализованный результат 4. Для поиска первого клиента с заданным номером выберите словарь, если запросов много; для единственного запроса сравните стоимость его подготовки с простым проходом.
